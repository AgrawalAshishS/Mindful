### Test Suite 1: Basic App Tracking (15 minutes)

#### Test 1.1: Simple App Session Tracking
**Steps:**
1. Enable Accessibility Service for Mindful
2. Open Chrome, use for exactly 30 seconds (use timer)
3. Press Home button
4. Check database using adb:
   ```bash
   adb shell "run-as com.mindful.android sqlite3 /data/data/com.mindful.android/databases/usage_events.db 'SELECT package_name, duration/1000 as seconds FROM usage_events ORDER BY _id DESC LIMIT 1;'"
   ```

**Expected Result:**
- One session for Chrome
- Duration ≈ 30 seconds (±2 seconds tolerance)

**Pass Criteria:** Duration within 28-32 seconds

---

#### Test 1.2: Multiple App Sessions
**Steps:**
1. Open Instagram, use for 20 seconds
2. Switch to Twitter, use for 15 seconds
3. Switch to Facebook, use for 10 seconds
4. Press Home
5. Query database:
   ```bash
   adb shell "run-as com.mindful.android sqlite3 /data/data/com.mindful.android/databases/usage_events.db 'SELECT package_name, duration/1000 FROM usage_events ORDER BY _id DESC LIMIT 3;'"
   ```

**Expected Result:**
- 3 sessions: Instagram (~20s), Twitter (~15s), Facebook (~10s)
- Sessions in correct chronological order

**Pass Criteria:** All durations within ±3 seconds

### Test Suite 4: Edge Cases (20 minutes)

#### Test 4.1: Accessibility Service Disabled by User
**Steps:**
1. Open Instagram, use for 15 seconds
2. Go to Settings → Accessibility → Disable Mindful service
3. Wait 5 seconds
4. Enable Mindful service again
5. Open Twitter, use for 10 seconds
6. Query database for sessions

**Expected Result:**
- Instagram session: ~15 seconds, properly closed
- No gap or overlap in sessions
- Twitter session: ~10 seconds, new session started

**Pass Criteria:** Both sessions recorded correctly, no data loss

---

#### Test 4.2: Accessibility Service Killed by System
**Steps:**
1. Open Facebook, use for 20 seconds
2. Use adb to stop the accessibility service:
   ```bash
   adb shell am force-stop com.mindful.android
   ```
3. Wait 5 seconds
4. Open Mindful app (triggers service restart)
5. Open Instagram, use for 15 seconds
6. Query sessions

**Expected Result:**
- Facebook session: ~20 seconds, closed when service stopped
- Instagram session: ~15 seconds, new session after restart

**Pass Criteria:** Sessions properly bounded, no orphaned sessions

---

#### Test 4.3: Rapid App Switching
**Steps:**
1. Rapidly switch between apps every 2 seconds:
   - Chrome (2s)
   - Instagram (2s)
   - Twitter (2s)
   - Facebook (2s)
   - YouTube (2s)
2. Press Home
3. Query last 5 sessions

**Expected Result:**
- All 5 sessions recorded
- Each duration ≈ 2 seconds
- No missing sessions
- No overlapping sessions

**Pass Criteria:** All sessions present, no gaps or overlaps

---

#### Test 4.4: Midnight Boundary Crossing
**Steps:**
1. Set system time to 11:58 PM
2. Set Instagram launch limit to 3
3. Launch Instagram 3 times (reaches limit)
4. Try 4th launch (should block)
5. Set system time to 12:01 AM (next day)
6. Trigger midnight reset:
   ```bash
   adb shell am broadcast -a com.mindful.android.MIDNIGHT_ACCESSIBILITY_RESET
   ```
7. Try launching Instagram again

**Expected Result:**
- Before midnight: 4th launch blocked
- After midnight reset: Launch allowed (count reset to 0)

**Pass Criteria:** Launch limit resets at midnight

---

#### Test 4.5: Restriction Update While App Running
**Steps:**
1. Open Twitter (no restrictions)
2. While Twitter is open, go to Mindful and set timer to 1 minute
3. Return to Twitter
4. Wait 1 minute

**Expected Result:**
- Timer starts counting from when restriction was added
- Block appears after 1 minute from restriction update

**Pass Criteria:** Restriction applied in real-time

---

#### Test 4.6: Emergency Pause
**Steps:**
1. Set Instagram timer to 1 minute, use for 30 seconds
2. Enable Emergency Pause in Mindful
3. Use Instagram for 2 minutes (should not be tracked)
4. Disable Emergency Pause
5. Continue using Instagram for 30 seconds
6. Check if block appears

**Expected Result:**
- During emergency pause: No tracking
- After disable: Tracking resumes at 30 seconds (not 3 min)
- Block appears after total 1 minute usage (30s + 30s)

**Pass Criteria:** Tracking paused correctly, resumes properly

## 7. Known Issues & Limitations

### Issues to Document:
1. **Flutter UI References**: Flutter code still references Usage Stats permission
   - **Impact**: Cosmetic only - shows unnecessary permission in UI
   - **Fix**: Update Flutter permission pages (low priority)
   - **Workaround**: Android side mocks the call, returns true

2. **Unit Test Mocking**: Complex tests need Mockito setup adjustments
   - **Impact**: Some tests may not run initially
   - **Fix**: Adjust mocking for Robolectric environment
   - **Workaround**: Database tests work, component tests need fixes

3. **Browser URL Detection**: Some browsers don't expose URLs
   - **Impact**: Cannot track/block websites in those browsers
   - **Fix**: None - inherent limitation of accessibility approach
   - **Workaround**: Document supported browsers

### Inherent Limitations:
1. **Accessibility Permission Required**: Users must grant permission
2. **System Can Kill Service**: Rare but possible under extreme memory pressure
3. **URL Detection**: Limited to browsers that expose URLs in accessibility tree
4. **Settings App**: Cannot track time in system settings (security restriction)
