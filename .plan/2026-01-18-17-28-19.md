# Implementation Plan: Web Time Limits & Database Schema (Execution Phase)

## 1. Requirement Analysis
We are implementing "web content restrictions (may include new time-based rules)".
Current progress:
- `UsageDatabaseHelper` exists for App Usage.
- `BrowserManager` exists but only does blocking, not time tracking per domain.
- `Wellbeing` model needs updates to support time limits per domain.

## 2. Flutter Side Updates
*   **Database Schema**: Update `WellbeingTable` in `lib/core/database/tables/wellbeing_table.dart`.
    *   Add `websiteTimeLimits` column (Text, JSON encoded Map<String, int>).
*   **Model**: Update `Wellbeing` generated class (via `build_runner` or manual if needed, but usually `build_runner`). Since I can't easily run `build_runner` to completion without errors in this env, I might need to carefully update generated files if I touch them, or rely on `drift` dynamic definitions.
    *   Actually, I can run `flutter pub run build_runner build` if I fix the environment, but often it's flaky. I should try.
    *   Alternatively, I can add the field and manually update the `g.dart` if I have to, but standard way is `build_runner`.
*   **Provider**: Update `WellbeingNotifier` in `lib/providers/restrictions/wellbeing_provider.dart` to expose methods to set limits.

## 3. Native Side Updates (Android)
*   **Model**: Update `Wellbeing.kt` in `android/app/src/main/java/com/mindful/android/models/Wellbeing.kt` to include `websiteTimeLimits: Map<String, Long>`.
*   **Storage**: Create `WebUsageDatabaseHelper` (SQLite) in `android/app/src/main/java/com/mindful/android/helpers/storage/WebUsageDatabaseHelper.kt`.
    *   Table: `web_usage` (`_id`, `domain`, `date` (millis at midnight), `usage_time` (millis)).
    *   Method `addUsage(domain: String, timeMs: Long, date: Long)`.
    *   Method `getUsage(domain: String, date: Long): Long`.
*   **Logic**: Update `BrowserManager.kt` in `android/app/src/main/java/com/mindful/android/services/accessibility/BrowserManager.kt`.
    *   Add `startTracking(url: String)` and `stopTracking()`.
    *   In `blockDistraction`:
        *   Detect URL change.
        *   If URL host changes:
            *   Stop tracking previous host (calculate duration, save to DB).
            *   Start tracking new host.
        *   Check if new host has time limit in `Wellbeing`.
        *   Check if limit exceeded using DB.
        *   If exceeded, block.
